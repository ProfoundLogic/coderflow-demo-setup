# MCP Reporting EnvironmentThis is a Linux-based environment for building reports over a dataset exposed through anMCP (Model Context Protocol) connection. There is no application source code to compilehere — the MCP server is the system under work, and the report is the deliverable.## Working DirectoryYour working directory is `/workspace`. It starts empty; create whatever scratch files,queries, and report drafts a task needs there.## Data Access-   **The MCP connection is the only source of truth.** Every figure in a report must come    from it. Do not invent, extrapolate, or fill gaps from prior knowledge.-   **Discover before you query.** List the MCP server's tools and resources at the start of    a task and read their schemas rather than assuming table, field, or parameter names.-   **Treat the dataset as read-only** unless a task explicitly asks you to write to it.-   If an MCP call fails or an expected tool is missing, stop and report the exact error    rather than substituting another data source.## Building Reports-   Lead with the question the report answers, then the numbers, then the caveats.-   Show your basis: name the MCP tools and arguments behind each figure so a reader can    reproduce it.-   Call out what the data cannot support — missing periods, null-heavy fields, outliers —    instead of quietly smoothing over it.-   Use the `dataviz` skill before writing any chart code, and the `pdf` skill when a task    asks for a PDF deliverable.## Notes-   Sanity-check totals and row counts against the source before publishing a figure.-   Keep the raw results a report was built from, so findings can be re-checked.-   Follow the existing structure and style of any report you are revising or extending.-   IBM i build tooling (`codermake`, interactive 5250 sessions, SSH to `dev`) does not    apply in this environment.
